# Reference output

[`command-output.html`](command-output.html) — what every command prints, in colour, ordered the
way you meet them: first install → first repo → first delegated job → second machine.

**Open it in a browser.** It is a standalone file with no server and no build step.

## Why an HTML file in a docs tree that has none

Markdown cannot hold colour, and colour is most of what was being decided. The page pairs, per
command, the output as it is today with the agreed form for a terminal and the agreed form for
a non-TTY consumer.

**It is a picture, and pictures drift.** The executable truth is
[`../../tests/golden/render/`](../../tests/golden/render/): exact bytes, ANSI escapes included,
asserted byte-for-byte and regenerated by hand. Where this page and a golden fixture disagree,
**the fixture is right and this page is stale.**

## What it settles

| | |
|---|---|
| Table shape | `STATUS · NAME · DETAIL · TIME`, everywhere. Status first, always a word. |
| Symbols | None. A tick that only appears on a TTY means the two modes have different shapes. |
| Log paths | Only on failure. Five paths for five passing checks is five lines nobody reads. |
| Durations | Humanised — `26.8s`, not `26754ms`. Milliseconds stay in `--json`. |
| `status` OWNS | Real resource ids, not counts. A count tells you neither what `clean` will remove nor what to go and look at. |
| Onboarding | `config scan` offers to hand over to an agent; the loop asks per task, not per file, and ends on a real `config verify`. |
