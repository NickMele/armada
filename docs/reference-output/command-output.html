Armada — what every command prints

Ordered the way you would actually meet them: first install → first repo → first delegated job → second machine. Where a command exists today, the now panel is real output captured from the binary, not reconstructed.

Most of this is unbuilt — Manifest is the only module that exists. Those sections are pure proposal, which is the point of reviewing them before an agent writes them.

Every proposal has a non-TTY form: what an agent reading stdout gets. Same columns, same words, no colour. Agents call this CLI constantly and mostly do not pass --json.

Then the loop, which is a conversation and not a generator. The agent reads more than the scan — README, AGENTS.md, CONTRIBUTING — then walks you through it one task at a time, because the whole failure mode is a config that looks right and encodes how nobody works.

› ▏
Two things make this a loop rather than a wizard.
1. It asks per task, not per file. "Is this how you run tests?" is answerable; "review this YAML" is not.
2. It does not stop until you both say so, and the last thing before "good to go" is always a real config verify — so "configured" means verified, never asserted.

✓ Settled: Manifest may be agent-aware in its output. ARCHITECTURE.md §1.9 governs inputs — Manifest may never accept a Job id, a model name or a transcript, or decide anything from one. Printing a choice and exec'ing into claude is neither: it is the same shape as fleet board handing you claude --resume. Manifest consumes nothing an agent produces, so the rule holds.
armada manifest config verify
pass 1 — static · nothing is executed

  STATUS      CHECK          DETAIL                             TIME
  PASS        schema         —                                  0.1s
  PASS        references     needs:, match:, ports fit block    0.1s
  FAILED      argv[0]        `vitest` not on PATH or in root    0.2s

FAILED  pass 2 not attempted · fix pass 1 first
  → web:test declares `vitest run`; did you mean `pnpm exec vitest run`?
The unchecked row is the honest cost of shell: true — there is no argv[0] to resolve in a shell string, so verify counts them rather than guessing or silently passing them. Worth seeing, which is why it has a row rather than a footnote.

Pass 2 is a real run, not a simulation — it runs the check suite exactly as check would, which for a big repo is a real build. Only pass 1 is seconds.

Three changes worth confirming.
1. Log paths only on failure. Five paths for five passing checks is five lines you never read.
2. Durations humanised — 26.8s not 26754ms. Milliseconds stay in --json.
3. Status is the first column everywhere, coloured or not. Symbols were dropped entirely — a ✓ that only appears on a TTY means the two modes have different shapes, and one shape is the point.

CLEAN  in 0.3s
Every table now has the same columns: STATUS · NAME · DETAIL · TIME. Status is always first and always a word, so it reads the same with colour and without. That gives the skipped release row a status instead of a bare ! — it was the one line with no way to tell "deliberately not run" from "went wrong".

A clean run with nothing to do keeps the table and shows — per row, so "nothing was owned" never looks like "something failed".

Decide: the current help lists every flag for every verb on one screen. The proposal moves per-verb flags behind armada manifest check --help. Faster to scan, one more keystroke when you have forgotten a flag name.

Underneath all of it · the rules

colour      only when stdout is a TTY and NO_COLOR is unset
progress    stderr, always — never stdout
columns     every table is STATUS · NAME · DETAIL · TIME, status first
symbols     none. A tick that only shows on a TTY means two different shapes
--json      unchanged, byte for byte. Golden snapshots prove it
width       narrow terminal truncates a column, never wraps a row
banner      bare `armada` and `armada init` only

The non-TTY column is the one that matters most in practice: agents call this CLI constantly and mostly do not pass --json. It is a first-class mode, not a degraded one.
