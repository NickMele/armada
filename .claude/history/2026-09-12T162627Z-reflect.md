## What is worth knowing next time

**A flake, named rather than explained.** One screens test reported
`1 failed | 625 passed` on `expect(rejected).toEqual([JOB.id])`, then passed on
the next run against identical code. It appeared while three heavy suites ran
concurrently in one batch and has not reproduced since. It is a run-sheet
assertion and nothing in this session's diff reaches it. Not fixed, not
understood, and recorded here because a red run reported as green is how a real
failure gets missed.

**Adjacent JSDoc blocks are one block to the gate.** Splitting a 19-line doc
into two `/** */` blocks on the same property made it 20 lines, because the rule
counts consecutive lines starting `*`. It is also wrong on its own terms: only
the last block attaches. A paragraph about the component belongs in the file
header, not in a second doc comment.

**Assert the span, then write.** Two edits refused to write tonight because a
verbatim span did not match — once from a reconstructed indentation, once from an
off-by-one slice. Both times the file was left untouched and the retry was
cheap. Three files had to be restored earlier in the session from edits that did
not assert first.
