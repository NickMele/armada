Twenty-seven `play` functions landed across seventeen story files, taking the
gate's baseline from `main` afterwards found that `main` could not pass its own
`test` Check, and closing the last loose end gave `packages/screens` the browser
suite the layer split was built for.

## The baseline was the finding

`cargo nextest run --workspace --exclude acceptance` failed on `main` at
972/1537 and 983/1537 across two runs, on `fleet tests::silence::*`. That is
the `test` Check in `armada.yml`, so every Job dispatched against this
repository was failing its first gated step whatever its Drone did.

This session touched no Rust. The failure was found only because the skill
requires taking the baseline from `main` in the same pass rather than from a
brief — a branch-only run would have shown one failure, been read as this
session's, and cost the evening.

`a_drone_that_keeps_talking_is_never_poked` slept 40ms and then asserted a
talking Drone was left alone. Under load the shell had not been scheduled, so
the Drone was silent, the vigil poked it correctly, and the test failed saying
a talking Drone was poked. The assertion was sound and its precondition was
never established, which is why it read as a Fleet bug rather than a test bug
for as long as nobody looked.

`armada/test-flakiness-under-load` had diagnosed the same class in two other
lines on 17 August, with measurements, and was never filed as an issue. A plan
commit on an unmerged branch is not a durable home.

## What a play is for, written down

`packages/components/vitest.config.ts` cited `docs/practices/react.md` as the
standard for a rendered assertion and the document never said it. The citation
resolved to nothing, so an agent following it learned nothing.

Two things cost time here and neither is guessable. A pointer left resting on a
chip keeps a hover-opened card open, so an assertion that the layer closed
passes against a component that has stopped pinning entirely. And an element
with no role has to be found through the structure, because its class is what a
refactor moves.

`JobDiffSheet`'s rail carried the open file in `data-on` and the stylesheet
alone. Asserting that would have been a test of the stylesheet wearing a test's
clothes, so the row took `aria-current` — which `StepRow` already used for the
same fact.

## What was found by not trusting a note

Two follow-ups this file first carried were stale, and both were read as open
work until the code was checked rather than the note.

`cost: 2` on `armada:test` describes a scheduling model that no longer exists:
there is no `cost` field on a Check and no `CpuSlot` in `crates/`. The live
question is `AT_ONCE = 4` against a concurrency cap of two — eight Checks and
two Drones on one machine — which `crates/fleet/src/checking.rs` states itself
and #284 already carries with its measurement.

#330 named a `storybook dev` server as the likely trigger for a run reporting
twelve failed files and zero failed tests. The session that filed it disproves
it: two later runs passed with that server still up. Closed, to be reopened on
a second occurrence.

## The last loose end took two places, not one

`Dialog` refuses a blank required field twice and independently — `disabled` on
the button, and its own `if` inside the `window` keydown handler — and nothing
asserted the second. Three screens set the prop, all on `trim()`, and all three
are acts nothing takes back.

The screen half could not be a story. `xtask/src/rules_layers.rs` puts
`@armada/components` below `@armada/screens` and refuses the import upward, so
`packages/components/src/screens/` is a frame assembled from primitives rather
than this repository's screens — and asserting a screen against that is the
failure the 2026-09-01 reflection recorded, where both halves of a green result
came from one wrong fixture. So `packages/screens` got the browser project its
own layer rule was written to make possible.
