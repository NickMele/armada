The `evidence:` design was re-explored with the owner and rebuilt around what it
actually is — a command the repository owns that leaves files behind, not a web
server that has to be probed — and the twenty issues that carried it are closed.
This run reconciled the one sentence that redesign left untrue and moved the
owner's Fleet onto protocol 13.5.

## What the redesign settled

| Was | Is |
|---|---|
| `evidence:` required `serve` + `ready` + `run` | `serve`/`ready` are an optional pair; a repo with no port declares `run` alone |
| `shown` was an evidence type | Capture and submission are separate — `captured: true` on a step asks Fleet to capture; `evidence.type` says what the step submits |
| One evidence type per step | A step may submit several |
| A bundled workflow in a repo with no `evidence:` refused | It skips capture and warns on the Job |

## What this run corrected

`docs/concepts/judge.md` still described a picture as an evidence type in
`[judge-visual-evidence-reading]`, which stopped being true when `shown` was
removed. The question is real and stays open; its text no longer asserts the
thing the work made false. `docs/OPEN.md` regenerated from it.
